## 2. Product decision

Build a current, decision-first English wiki for the X-to-Z search transition. The main opportunity is not to repeat a generic UTD database. It is to answer the renamed game's current codes, 4.0 event routes, new-unit acquisition, unit investment, traits, relics, and progression questions while making the identity transition explicit.

This is a broad Roblox tower-defense game with strong demand and usable sources, so the launch target is roughly 40-50 English URLs. The route count comes from useful hubs, selected unit details, and substantive guides—not hundreds of thin entity pages.

## 3. Research snapshot

### Official facts

- Roblox describes the loop as summoning units, defending waves, playing multiple modes with friends, leveling units, Etherealizing them, and evolving them.
- The July 10 API snapshot showed more than 282M visits and a large live player count, supporting a broad launch rather than a thin 8-page site.
- Current official media changes the wordmark from X to Z and uses red, black, warm cream, and high-contrast manga artwork.
- No separate standalone official website was verified. Roblox and the verified creator group remain the official identity layer.

### Search transition

Serper balanced discovery used three seeds and about six credits: `universal tower defense z`, `utdz`, and `universal tower defense z update 4.0`.

- Exact Z autocomplete is still polluted by `zoro` unit searches and falls back to UTDX terms.
- Related searches preserve strong demand for tier list, codes, Roblox, Discord, and wiki.
- Update 4.0 autocomplete already expands into codes, wiki, and patch-version variants.
- The content must use both `Universal Tower Defense Z` and `UTDZ`, while mentioning former name UTDX only where it resolves identity confusion.

## 10. Data and freshness rules

- Codes: publish only the five July 9 active codes cross-checked by current trackers; move old 3.x codes to expired.
- Tier list: clearly state the 4.0 transition and use roles/account stage rather than pretending every new unit has a stable rank.
- Units: selected late-X/current-experience records are useful but not a complete 4.0 database.
- Update pages: use current YouTube/official signals, but avoid unsupported exact mechanics.
- Store checked dates and source URLs in data. Keep detailed QA notes out of public debug cards.
